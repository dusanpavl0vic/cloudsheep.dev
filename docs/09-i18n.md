# 09 — Internacionalizacija

> Status: active | Last review: 2026-10-08

next-intl 4 (API `use-intl`: `useTranslations`, `getTranslations`). Jezik javnog sajta je u URL-u
(ADR 0012); admin čuva jezik u `preferences` slice-u.

## 1. Fajlovi

```
constants/i18n/
  locales.ts    LOCALES, Locale, DEFAULT_LOCALE, LOCALE_LABELS, LOCALE_TAGS, OG_LOCALES — bez poruka
  en.ts         izvor istine za oblik: const en = { common: {…}, nav: {…}, … }; export default en
  sr.ts         const sr: Messages = { … } — TypeScript prijavljuje svaki ključ koji fali
  types.ts      Messages = DeepString<typeof en>, MessageNamespace
  messages.ts   MESSAGES — uvozi ga SAMO server (i18n/request.ts)
  index.ts      locales + tipovi (bez poruka)
i18n/
  routing.ts    defineRouting: en/sr, as-needed, bez detekcije
  navigation.ts Link, useRouter, redirect sa prefiksom
  request.ts    poruke za serverske komponente
  locale.ts     bindRequestLocale (jedino mesto sa zastarelim setRequestLocale)
types/use-intl.d.ts   tipizovani ključevi u t('...')
```

`locales.ts` je odvojen od poruka namerno: klijentska komponenta koja prikazuje izbor jezika ne
sme da povuče sve prevode u svoj bundle.

## 2. Ključevi

- Grupisani po namespace-u domena (`home`, `projects`, `contact`, `admin`…); deljeni tekstovi u
  `common`, `nav`, `errors`, `meta`.
- Novi ključ: prvo `en.ts`, pa `sr.ts`. Tip `Messages` garantuje da se ne razilaze.
- ICU: `t('count', { count })` sa `{count, plural, one {…} few {…} other {…}}` — srpski ima
  `few` (2–4).
- Bez literal stringova u JSX-u — lint `i18next/no-literal-string`.

## 3. Gde se prevodi

| Komponenta                      | Kako                                                       |
| ------------------------------- | ---------------------------------------------------------- |
| serverska (bez hookova)         | `const t = useTranslations('home')` — radi i na serveru    |
| `page.tsx` / `generateMetadata` | `await getTranslations({ locale, namespace: 'meta' })`     |
| klijentska                      | `useTranslations` — namespace mora biti prosleđen klijentu |

**Klijentu ide samo ono što mu treba.** `I18nProvider` u ljusci šalje `SHELL_NAMESPACES`
(`common`, `nav`, `theme`, `language`, `errors`). Ostrvo sa mnogo teksta (upit, procena) se umota
u svoj `I18nProvider namespaces={['contact']}` na stranici. Najbolje je ipak da serverski roditelj
prevede tekst i prosledi ga klijentskoj komponenti kao prop — prevod tada uopšte ne putuje u JS.

## 4. Formati

Datumi i brojevi kroz `useFormatter()` / `getFormatter()` (next-intl), sa `INTL_LOCALES`
(`en-GB`, `sr-Latn-RS`). Vremenska zona je uvek `Europe/Belgrade` (termini poziva su u CET).

## Anti-patterns

| ❌                                                    | ✅                                                              |
| ----------------------------------------------------- | --------------------------------------------------------------- |
| `<NextIntlClientProvider>` bez `messages`             | prosledi samo potrebne namespace-e                              |
| `import { MESSAGES }` u klijentskoj komponenti        | `useTranslations`                                               |
| `import { LOCALES } from '@/constants/i18n/messages'` | `from '@/constants/i18n'`                                       |
| `t('nav.' + key)`                                     | ključevi iz konstante tipa (`NavKey`) — tipovi ostaju provereni |
